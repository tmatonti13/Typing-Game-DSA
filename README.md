In this project my intention was to create a typing game that displays an assortment of words
across a Java Swing window, and allow the user to type the words and receive some sort of feedback
as to whether or not what they typed was correct/incorrect. My motivation centrally came from the online typing game “monkey type” ( monkeytype.com ). I have been playing this game since high school and I feel that it has significantly helped me improve my typing in multiple facets: my words per minute, accuracy, and spelling. 

At first I tried using a text input box at the bottom of the screen that would let the user type in the entire displayed sentence in one go, and then they would have to press the enter key to move on to the next sentence. This original model had several shortcomings however, the user would not know what they typed incorrectly until they went back and scanned their sentence. They would also have to press the enter key every time they wanted to move onto the next sentence. The process became inefficient for the fast paced typing game I was aiming for. So I decided to take a different approach, and use a key listener to track individual user inputs rather than using the text box. This is how I maneuvered around this issue, and found much success in that way. In the original model, only 10 words were displayed at a time and then another 10 would appear when the user pressed enter. My workaround for this was to implement a random word generator that displays 10 words at a time, and once 5 words are typed by the user the sentence will buffer to the left and more words will be displayed in real time as the user types. This streamlined the process making it much easier to type at faster speeds. Then finally updateDisplay() method allows for the visual rendering of all words in the buffer and then dynamically colors the current word as the player types. It highlights correct letters in green, mistakes in red, and adds a caret to simulate real typing. Words already typed appear in gray, while upcoming words stay black, including live feedback to supplement the statistics. After the user is done typing, a menu pops up with the results of the typing session. The game will give total score (10 points per correct word typed), then the amount of correct, and incorrectly typed words, along with an accuracy % and a words per minute calculation. All to give the user insights regarding their typing experience. 

Some bugs I encountered during this process occurred when I changed my typing method. When I went word by word to check for correctness, the user could continue typing and the program would not display where the user currently lies. So what I did was I made sure the incorrect words would be added onto the end in red and would show the incorrectly typed letters to the user so they know what they needed to correct. One thing I wanted to implement but was unsure so I underwent some researching, was how to change the color of the text based on the users’ inputs. After some searching on Oracle (https://docs.oracle.com/javase/tutorial/uiswing/components/html.html) I discovered that you can use HTML to do just this. 

The words are loaded in from an imported file. As you run the program, the user is prompted with a panel by using the JOptionPane that prompts the user with a dropdown menu asking the user to select their preferred typing time. Once the time is selected the typing window appears and the user can begin typing. I used an action listener to detect user typing input, looking for backspaces or any character types. When the user types, the words shift across the screen. This is done with The initBuffer(), and scrollBuffer() methods. These methods manage the visible words that appear on the screen. The buffer is initialized with random words from a preloaded word list, and as the user types, words are scrolled out and replaced to simulate a continuous typing experience for the user. This is helpful for faster typers who would like to see the upcoming words ahead of time as they are actively typing. Then, the typeCheck() method processes each typed character. When the spacebar is pressed, it checks if the typed word matches the current word in the buffer. If correct, it increments the score and correct word count, otherwise, it counts as an error. After processing, the buffer scrolls to simulate a moving stream of words, and then the display is refreshed to reflect the current game state. 

If I had more time to peck away at this project there are certainly some things I would have loved to add. First I would have liked to have added a menu that allows for file selection so the user can decide what they want to type, whether it is common/uncommon words, a quote from a passage, or a book of sorts. I could not quite pinpoint how I was going to go about this so I decided to scrap the idea. Another feature I would also have liked to add would have been a profile for the user. Being able to track your progress and improvement is one of the rewarding parts of committing to better yourself in a certain field. Something else I would have liked to add would definitely be a visual aspect to the game. Like after the user finishes their typing session something would pop up to give the typer some insights. This could be an accuracy and WPM graph, or something along those lines. And then this feature could work in tandem with the user profile feature as the users' continued typing could maybe contribute to like a lifetime graph showing progress over time. There is a lot I can do with this and I feel like this is a great game idea with lots of avenues that could be taken. 

Overall I am very pleased with the outcome of this project as this has been something I wanted to work on for a long time and I am glad I was able to see it come to fruition.
